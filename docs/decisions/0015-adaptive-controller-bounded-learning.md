# ADR 0015 — Adaptive strategy controller: bounded learning outside the safety constraints (M6)

Status: Accepted. The learned controller is **implemented, gated and opt-in; it did not beat the rule baseline at the frozen parameters**, so the rule baseline stays the default and nothing was promoted. Evidence: [design](../experiments/adaptive-controller-design.md), [report](../evaluations/adaptive-controller-report.md), [tables](../evaluations/adaptive-controller-tables.md); operating guide [controller.md](../controller.md).

## Context
M5/M5.10 left one fixed decision rule (`rule-capability/1`: use the best eligible capability, plan otherwise) and showed that a capability can be good, or stale and costly, depending on the portfolio. M6 asks whether a controller can learn when to use a capability, under the architecture rules: decisions are logged with propensities, hard constraints stay outside learned optimisation, nothing learned is activated without independent evidence, and execution never waits for learning.

## Decisions
1. **Constraint layering.** Eligibility (matcher) → feasibility (rule default, feasible set, protected classes) → reliability (non-inferiority bound vs the default, optional absolute floor, minimum evidence per cell) → cost objective (expected tokens per verified success, only among admissible actions) → exploration. `high` risk is not representable as a learned class; protected classes and foreign tenants get the rule decision with probability 1.0 and no estimate read. The orchestrator still refuses a capability the matcher did not admit.
2. **Tabular, auditable estimator.** `(family, risk, action)` cells of verified acted outcomes (UNKNOWN and shadow excluded), shrinkage on cost, prequential calibration (ECE gate; Brier skill reported only, design A1). Chosen over richer models because the only decision-time features that carry signal here are family, risk and the offered capability, and because every decision must be recomputable.
3. **Policies are immutable, hashed versions** (`ControllerPolicyDefinition`); the rule baseline remains the default action of every adaptive policy. Cost-aware (deterministic) and bandit (ε-greedy, gated by data and an explicit family/risk allow-list, exact logged distribution, hash-derived uniform draw) kinds.
4. **Rollout is a registry with evidence, enforced twice.** CANDIDATE → SHADOW → CANARY → ACTIVE need stored PASS evidence of the previous stage for the same definition hash and gate set; the database re-checks it (trigger), keeps one SHADOW/CANARY/ACTIVE per policy (partial unique indexes), and history is append-only. Rollback restores the superseded version atomically; REJECTED/ROLLED_BACK are terminal. A canary FAIL rolls back automatically.
5. **Shadow is first class.** `TaskOrchestrator(shadow=...)` records a non-acted decision (`policy_decisions.acted=false`, migration 0005) and isolates its failures.
6. **Evaluation protocol frozen before data**, with a three-valued paired verdict (BEATS / EQUAL / WORSE / INCONCLUSIVE; design A2) that charges exploration cost and never lets tokens offset lost success. Four amendments (A1–A4) were made before any recorded or real-model result; one fixture redesign after a development run (design §12), all documented.

## Findings (details and caveats in the report)
* **Mechanism works** on synthetic worlds with known truth: equal to the rule when the rule is right, recovers when it is wrong, never trades success for tokens, never deviates on protected tasks, adapts to drift with a training window.
* **Real recorded data, rule right (M5.10 sets C, D):** cost-aware EQUAL (never deviates); the bandit pays a measurable one-off exploration premium (WORSE under the frozen rule when primed from a rule-only log: about −3 points success and +8–10% tokens per verified success over a 120-task stream; EQUAL when cold-started because the data gate delays exploration).
* **Real fresh data, rule wrong (stress portfolio, held-out H1):** a stale timeout capability costs +54% tokens per verified success for the same success, but the controller did **not** beat the rule baseline at the frozen defaults (cost-aware EQUAL, bandit EQUAL). Confirming non-inferiority of an alternative explored ~5% of the time needs far more than 120 tasks. Post-hoc sensitivity (labelled exploratory, not a basis for adoption) shows BEATS with ε 0.2–0.3 over 1500–3000-task streams, at an exploration cost of about 26 lost successes per stream.
* A constant ε is a poor fit for stationary regimes: the evidence-gathering premium is paid whether or not the rule was wrong.
* Live shadow/canary on the real model exercised the full registry path (offline PASS, shadow PASS, canary PASS at 60/60, 180/180 stored decisions replayed exactly) and **caught a defect in my canary evaluation**: the first comparison used all earlier control traffic instead of a concurrent window, and an ACTIVE promotion rested on it. Fixed (canary window, same-population control, evidence-not-before-canary check in the registry, canary evaluation only in the CANARY state), covered by regression tests, and the unjustified promotion was rolled back with the full audit trail kept. The corrected evidence also passes at 60/60, but the candidate behaved like the rule baseline (1 deviation in 60), so no controller benefit is shown.

## Consequences
* Keep `rule-capability/1` as the default controller. `ee-ctl`, the registry and the shadow hook are available for operators; adopting a learned policy requires stored PASS evidence at every stage and a fresh confirmation.
* Before any adoption: replace constant ε by evidence-driven allocation (explore until the bound resolves, then stop), consider variant-level features (the tabular estimator cannot see within-family variant differences), size the canary from the margin (about 100–135 tasks per arm for a 10-point margin when rates are equal and 50–75% success), and re-run a confirmation on a fresh seed.
* Learning cost of the controller is 0 model tokens (tabular training and replay); the cost to account for is validation runs and exploration, both reported.
* Not done: HUMAN_ESCALATION selection, contextual features beyond family/risk, multi-tenant pooled estimators, a cost model for latency, adaptive canary sizing.
