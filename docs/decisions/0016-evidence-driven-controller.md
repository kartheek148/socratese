# ADR 0016 — Evidence-driven controller: paired validation priors and bounded exploration (M6.1)

Status: Accepted as **implemented, gated and opt-in**. The pre-registered confirmation was met (`evidence+prior` equals the rule baseline when the rule is right and beats it on a stale capability at zero exploration cost), but only by a razor-thin margin in the prior and with a clear negative drift result. The rule baseline stays the default controller and nothing was promoted. Evidence: [design](../experiments/evidence-driven-controller-design.md), [report](../evaluations/evidence-driven-controller-report.md), [tables](../evaluations/evidence-driven-controller-tables.md); operating guide [controller.md](../controller.md). Builds on ADR [0015](./0015-adaptive-controller-bounded-learning.md).

## Context
M6 showed that constant-ε exploration is paid in every regime (about −3 points success and +8–10% tokens per verified success when the rule is right) and that proving non-inferiority of an alternative from live exploration needs on the order of 130 independent samples. Promotion already pairs baseline and candidate on held-out tasks; the M5.10 final-outcome arm (capability plus planner fallback) measures what production serves. The question for M6.1: can validation evidence replace most of the exploration?

## Decisions
1. **Paired priors, not pooled live data.** The estimator snapshot may carry per-cell 2×2 tables of the rule default and one alternative on the same held-out tasks (`PairedCell`), with source provenance (`PairedSource`: files, dataset hashes, model, runtime and verifier versions, counts, UNKNOWN/tied drops, task hash, validation tokens). Only held-out splits are accepted; repetitions collapse by strict majority; UNKNOWN is never a success or a failure; a source recorded under another runtime or verifier is refused unless `--allow-version-mismatch` records the override. The offline gate FAILs priors without complete provenance.
2. **Reliability bound is paired.** The lower bound of `p_alt − p_default` is the Newcombe (1998, method 10) paired interval (exact one-sided coverage 0.947–0.975 at nominal 0.95, tested by enumeration); an alternative replaces the rule default only if the bound is ≥ −δ for the risk class and it saves ≥ 10% tokens per verified success. Cost never compensates a failed bound. A prior-backed cell never explores (live unpaired data cannot tighten a paired bound).
3. **Evidence-driven exploration replaces constant ε** (kind `EVIDENCE_DRIVEN`, tier L only): explore an alternative only while its independent bound is unresolved, a saving is plausible (optimistic cost per success ≤ 90% of the default's) and its sample target (smallest n at which the bound could clear −δ if the point estimates held, capped at 400) is not reached. Same allow-list, data/calibration gates, exact logged propensities and hash-derived draw as the bandit; decisions replay exactly.
4. **Drift guard.** With ≥30 live outcomes, an alternative whose live success is confidently below its validation rate by more than δ (or a default confidently above its own) invalidates the prior and the rule default returns. Deliberately coarse.
5. **Backward compatibility is part of the contract.** New fields are optional and omitted from serialization when empty; `EVIDENCE_DRIVEN` and paired priors both require the evidence parameters; the stored hashes of `COST_AWARE` and `BANDIT` definitions and snapshots are pinned by a test and every earlier decision still replays. Migration `0006` only widens the `controller_policies.kind` CHECK (downgrade refuses while `EVIDENCE_DRIVEN` rows exist; history is not rewritten). `default-low`, `default-low-v2`, `serving-low-v1` and `rule-capability/1` are untouched.
6. **Protocol frozen before data.** Parameters, sizes (from a power analysis on development data only), the verdict rule at the controller's contractual 10-point margin and the acceptance criteria were committed before the fresh data were generated and before any held-out outcome was read.

## Findings
* **AC-R (rule right, H2-pool):** `evidence+prior` deviation 0%, exploration 0%, verdict EQUAL; the M6 bandit WORSE (−3.4 points, +9% tokens).
* **AC-S (rule wrong, H2-timeout):** with a 238-pair prior, deviation 100%, exploration 0%, verdict BEATS (27% fewer tokens per verified success, success difference −0.4 points, lower bound −5.9 inside the 10-point margin). Pre-registered decision: **SUPPORTED**.
* **Fragile:** the prior's lower bound was −0.0999 against −0.10; V's own estimates give a 0.53 chance that an independent 240-pair validation resolves (0.33 at 120, 0.66 at 360). Priors of 30/60/120 pairs left the rule in place (safe, no saving).
* **Negative:** under a synthetic mid-stream collapse of the alternative, the guard recovers only partly (success 30.7% with the guard vs 28.1% without; the rule baseline 47.5%) because it compares cumulative live evidence with the prior. Prior-backed policies are not drift-robust.
* **Cold evidence-driven** exploration is much cheaper than the bandit (3.8% / 0% of decisions vs 10.5% / 9.8%) but does not resolve the stale case within 236 tasks.
* **Cost:** prior validation 4.07M tokens as built (3.64M for the timeout cell, break-even ≈ 1,440 timeout tasks at 2,528 tokens saved per task); the promotion evaluator's capability-alone arm cannot seed a prior, so near-zero incremental cost needs M6.2.

## Consequences
* Operators can seed a policy with `ee-ctl train --kind evidence --paired-from RESULTS...`; the offline gate reports prior cells, pairs and validation tokens. Adoption still needs stored PASS evidence at every stage (shadow, canary) and a fresh confirmation; no M6.1 policy was promoted.
* Next: record the final-outcome arm in promotion validation (M6.2) so priors come for free; a windowed or sequential drift detector; variant-level features; size validation from the margin and observed discordance (`ee-ctl prior-curve`).
* Not done: contextual features beyond family/risk, multi-tenant pooled priors, latency cost model, automatic retirement of a stale capability.
